# parity-harness

**두 방향을 모두 본다.** 한쪽만 보면 "레거시와 같다"고 말할 수 없다.

| 게이트 | 무엇을 보는가 |
|---|---|
| `check_no_invention` | 레거시에 **없던 것이 생겼는가** |
| `check_completeness` | 레거시에 **있던 것이 사라졌는가** |

누락이 더 조용하다. 없던 버튼이 생기면 눈에 띄지만, 있던 버튼이 사라지면 화면이
멀쩡해 보인다. 그 기능을 쓰던 사람만 나중에 안다.

**레거시를 정답(golden)으로 삼아, 이관 결과가 원본과 같은지를 기계적으로 증명하는 마이그레이션 게이트.**

시중의 AI 마이그레이션 도구는 대부분 *변환*에서 멈춘다. 변환 결과가 맞는지는 사람이 눈으로 본다.
이 프로젝트의 전제는 반대다 — **변환은 쉽고, 정합성 증명이 어렵다.**

현재 구현된 게이트: `check_no_invention` (발명 차단)

---

## 왜 "발명 차단"이 첫 번째 게이트인가

LLM 기반 마이그레이션의 최대 실패 모드는 버그가 아니라 **친절함**이다.

레거시에 없던 엑셀 다운로드 버튼을 추가하고, 없던 "총 3건이 조회되었습니다" 안내를 넣고,
콤보박스에 없던 항목을 하나 더 만든다. 전부 그럴듯해서 **코드 리뷰에서 걸리지 않는다.**
그리고 운영에 나가서 "이 버튼 뭐죠?"로 돌아온다.

컴파일러도 테스트도 이걸 못 잡는다. 문법적으로 옳고, 동작도 하기 때문이다.
잡으려면 **레거시에 무엇이 있었는지를 정답으로 고정**해야 한다.

## 동작 원리

### 1. 모든 요소를 비교하지 않는다

레거시와 신규의 DOM 전체를 diff하면 레이아웃 wrapper 차이만으로 노이즈가 폭발한다.
**의미 있는 요소(significant element)** — 사용자가 인지하거나 상호작용하는 것 — 만 추출한다.

### 2. 스택 중립 signature 로 환원한다

```
kind : role | label | detail
```

| 레거시 | 신규 | signature |
|---|---|---|
| `<input type="submit" value="조회">` | `<button type="submit">조회</button>` | `control:button\|조회\|submit` |
| `<select id="ddlDept">` + `<label for>` | `<select id="deptCd" class="dx-selectbox">` | `control:select\|부서\|` |
| `<th>출근시각</th>` | `<th>출근시각</th>` | `column:header\|출근시각\|` |

태그도 클래스도 id도 다르지만 **같은 요소**로 인식된다. 이 정규화 계층이 게이트의 핵심이다.

### 3. 개수까지 센다

레거시에 저장 버튼이 1개인데 신규에 3개면 **2개가 발명**이다. multiset 으로 비교한다.

## 오탐 제어

게이트가 오탐을 내면 팀이 게이트를 꺼버린다. 미탐보다 치명적이다. 그래서:

| 장치 | 내용 |
|---|---|
| **서버 구문 전처리** | HTML 파서에게 `<%` 는 태그가 아니라 텍스트다. JSP 를 그대로 먹이면 자바 코드가 화면 텍스트로 새고, `%>` 의 `>` 가 태그를 조기 종료시킨다. 레거시/신규 양쪽에 동일 적용 |
| **value ≠ 라벨** | `<button value="delete">삭제</button>`, `<option value="10">경영지원</option>`, `<input name="unitName" value="<%=name%>">` — 전부 value 는 데이터고 라벨이 아니다. 버튼류 input 만 예외 |
| **위젯 래퍼 제외** | `<div class="dx-field"><input></div>` 에서 래퍼까지 세면 충실한 이관도 전부 발명으로 잡힌다. 잎 요소만 위젯으로 인정 |
| **표기 정규화** | 전각/반각(NFKC), NBSP, 연속 공백, 필수표시 `*`, 콜론 흡수. "사원번호 \*" == "사원번호:" |
| **동적 텍스트 환원** | 레거시 `<%= %>` 와 신규 `th:text` 를 동일한 `«dyn»` 자리표시자로. 값을 모르는 것끼리 비교하지 않음 |
| **세 갈래 분류** | 신규에만 있는 요소를 `invention` / `label_drift` / `detail_change` 로 나눈다. 조치가 완전히 다르다 — 아래 참조 |
| **hidden 키 안정화** | CSRF 토큰은 매 렌더 값이 다르다. 값이 아니라 `name` 으로 식별해야 allowlist 등록이 유지된다 |
| **allowlist** | 예외는 허용하되 **사유 10자 이상 필수**. 사유 없는 예외는 설정 오류로 게이트 자체를 실패시킨다 |

> 게이트를 끄는 방법은 있어야 한다. 다만 끄면 기록이 남아야 한다.

### 세 갈래 분류

신규에만 있는 요소를 뭉뚱그리면 리포트가 엉뚱한 조치를 지시한다.

| 분류 | 조건 | 심각도 | 조치 |
|---|---|---|---|
| `invention` | 대응물이 없다 | **HIGH** | 제거하거나 사유와 함께 allowlist 등록 |
| `label_drift` | 닮은 라벨이 있다 | MEDIUM | 레거시 원문 표기로 되돌린다 |
| `detail_change` | 라벨이 같고 대상만 다르다 | MEDIUM | 라우트 변경이면 의도된 것. **라벨은 건드리지 않는다** |

`detail_change` 가 없으면 라우트를 새로 설계하는 이관에서 모든 링크가
"표기가 틀어졌다"로 보고되고, 사람이 멀쩡한 라벨을 고치게 된다. ERFlow 사이드 메뉴에
실제로 17건이 여기 걸렸다 — 발명 0건, 라벨 드리프트 0건, 전부 라우트 변경.

## exit code 규약

```
0  PASS      정합성 확인됨
1  FAIL      위반 발견 (자동 보강 가능) -> self-loop 진입
2  ERROR     도구/설정 오류 (게이트 자체가 실행 불가)
3  ESCALATE  정답(golden) 부재로 판정 불가 -> 사람 판단 필요
```

**3을 1과 분리한 것이 설계의 핵심이다.** 정답이 없는데 통과시키지 않는다.
자동화의 신뢰성은 "모를 때 어떻게 행동하는가"에서 갈린다.

## 사용법

의존성 없음. Python 3.10+ 표준 라이브러리만 사용한다.

```bash
# 1. 레거시 화면에서 정답을 뽑는다 (손으로 쓰지 않는다)
python -m gates.extract_golden \
    --legacy fixtures/legacy/attendance.html \
    --screen attendance-list \
    -o golden/attendance.json

# 2. 신규 구현을 검사한다
python -m gates.check_no_invention \
    --golden golden/attendance.json \
    --new fixtures/new/attendance_invention.html
```

```
발명 의심 3건  (HIGH 2 / MEDIUM 1)  attendance_invention.html

  HIGH   attendance_invention.html:20
         control:button «엑셀 다운로드» [button]
         레거시에 대응물 없음
         조치: 요소를 제거하거나, 의도적이면 allowlist 에 사유와 함께 등록
         key: control:button|엑셀 다운로드|button
```

주요 옵션: `--allowlist` 예외 목록 · `--strict` MEDIUM 도 차단 · `--json` CI 연동 · `--no-text` 정적 텍스트 제외

## 테스트

게이트는 코드가 아니라 **판정 기준**이다. 기준이 틀리면 하위 판정이 전부 틀린다.

```bash
python -m unittest discover -s tests -t .
```

11개 케이스가 오탐/미탐 양쪽을 고정한다. 특히 `test_faithful_migration_passes` 는
DOM 구조가 완전히 다른(테이블 레이아웃 → flex, dx-\* 래퍼 추가) 충실한 이관이
통과하는지를 검증한다 — 오탐 회귀 방지선.

## 현재 범위와 한계

정직하게 적는다. 이 게이트는 만능이 아니다.

- **정적 마크업 대상.** JS 로 초기화되는 DevExtreme 위젯처럼 템플릿 소스에 선언이 없는 요소는
  이 게이트로 볼 수 없다. 서버 렌더링 결과물이나 실브라우저 DOM 을 입력으로 주어야 한다.
  → 실렌더 검증은 별도 e2e 게이트의 몫으로 분리한다.
- **공통 레이아웃은 범위 밖.** `<%@include file="/indexHeader.jsp"%>` 는 전처리에서 제거된다.
  헤더/사이드 메뉴는 145개 화면에 동일하게 들어가므로, 화면마다 검증하면 리포트가 레이아웃으로
  덮인다. 레이아웃 정합성은 1회만 별도로 본다.
- **`*Proc.jsp` 같은 처리 전용 페이지는 대상이 아니다.** 렌더링 결과가 없어 의미 있는 요소가
  0건이다(ERFlow 에서 실측 확인). 화면 게이트에 넣으면 전량 오탐한다.
  → 액션 정합성(파라미터·리다이렉트)은 별도 게이트로 분리한다.
- **"없어진 것"은 잡지 않는다.** 이 게이트는 발명(추가)만 본다.
  누락은 `check_completeness` 로 분리한다 — 조치와 심각도 기준이 다르기 때문이다.
- **의미적 동등성은 판정하지 않는다.** 라벨이 같으면 같은 요소로 본다.
  동작이 다른지는 e2e 검증 영역이다.
